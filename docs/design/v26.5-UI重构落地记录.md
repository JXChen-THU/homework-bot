## 零、统一重构：抽出一份共享主题表

### 为什么做

`index.html` / `panel.html` / `alert.html` 是**三个独立文档**，浮窗读不到 `main.css` 的
`:root`，所以同一套 token 原先在三个文件里**各写一遍**（70 个 × 3 份 = 210 条声明，
含暗主题层实际删除 **345 条**）。一处调整要同步三个地方 —— 这正是本项目反复出 bug 的根源：

* `--alert-mark` 只写在 `main.css` → 浮窗里解析成空值，呼吸点变透明、勾选框标识色丢失
* `--ink` 的暗色值在主窗口调亮了，两个浮窗还是旧值，一直没人同步

### 现在怎么做

新增 **`Work/web/theme-shared.css`**：只放 token（全文只有 `:root` 与 `html[data-lg-dark]` 两条选择器，
没有任何元素/类选择器，也没有布局属性）。

```html
<link rel="stylesheet" href="fonts.css">
<link rel="stylesheet" href="theme-shared.css">   <!-- 必须在页面样式表之前 -->
<link rel="stylesheet" href="main.css">
```

三个页面各自引入一次，位置在**各自页面样式表之前** —— 所以"某页特有的值"照旧能覆盖

## 一、三个页面的加载顺序（重建 · 以代码为准）

三份 HTML 完全同构，顺序一致（`web/index.html:6-11`、`panel.html:6-10`、`alert.html:6-10`）：

```text
theme-boot.js  →  fonts.css  →  theme-shared.css  →  main.css / panel.css / alert.css
```

- `theme-boot.js` 是 `<head>` 里一个**不带 defer/async 的外部脚本**（`<script src="theme-boot.js">`，
  阻塞渲染），必须放在最前面：它要赶在首帧绘制之前决定 `data-lg-dark`，否则会先闪一下浅色。
- `theme-shared.css` 在页面自己的样式表之前，是为了让"某页特有的值"仍然能覆盖共享值。

**共享表的规模**：`theme-shared.css` 96 行 / 81 处 token 声明（浅色一套，暗色只覆盖需要变的）。

**没有做完的部分（据实记录）**：三份页面样式表里仍有大量字面色值
（`main.css` 413 处、`panel.css` 103 处、`alert.css` 97 处，v26.5 清理后的计数）。
本次解决的是"同一套 token 各写一遍"，不是"所有颜色都 token 化"。

## 二、主题三态与跨窗口同步（重建 · 以 `theme-boot.js` 为准）

- 只写两个属性：`data-lg-dark`（暗色时存在、浅色时移除）与 `data-lg-mode`（恒为 `auto`/`light`/`dark`）。
  **代码里没有 `data-theme` 属性**（`data-theme-mode` 只出现在主窗口那三个切换按钮上）。
- `localStorage` 键名：**`hwThemeMode`**；读取异常一律回落 `auto`。
- 三态解析：`auto` → `matchMedia('(prefers-color-scheme: dark)')`；`light`/`dark` 直达；
  并用 `change` 事件跟随系统实时切换（旧引擎回落 `addListener`）。
- 跨窗口同步 = `storage` 事件：同源（`file:///…/web/`）的窗口共享 `localStorage`，
  改动会在**其他**窗口触发事件；写改动的那一方自己在 `setMode()` 里已经 `apply()` 过了。
- 出口 API：`window.hwTheme = { apply, mode, resolved, setMode }`。
- 两个浮窗的 `floating-common.js` 里有一份**同款兜底实现**：仅当 `!window.hwTheme` 时启用
  （保证浮窗先于主窗口加载时也有主题）。

## 三、字体（重建 · 以 `fonts.css` 为准）

- 别名声明：`HW-Kai` ← `fonts/楷体_GB2312.TTF`（400）；`HW-Times` ← `fonts/TIMES.TTF`（400）
  与 `fonts/TIMESBD.TTF`（700）。全部 `font-display: swap`。
- 一个栈搞定中英混排，浏览器逐字回退：**英文数字符号 → Times，汉字与中文标点 → 楷体**
  （实测 `TIMES.TTF` 的 cmap 只有 1592 个码位，没有 `— … “ ” ， ： （ ＋` 这些，会自然落到楷体）。
- `button, input, select, textarea, optgroup { font-family: inherit }`：否则表单控件在 Windows 上
  仍是 UA 默认的 Arial，界面会出现"按钮不是一套字体"的混搭。
- **v26.5 的减法**：两个斜体面（`TIMESI` 400 italic、`TIMESBI` 700 italic）已删除。
  依据是全仓没有任何 `font-style: italic`、也没有 `<i>/<em>` 标签，这两个面永远不会被选中；
  字样从 5 个 / 8,363,704 字节降到 3 个 / 6,496,636 字节。
  700 面**必须保留**：样式里有 12 处 `font-weight: 600`，按 CSS 字重匹配规则会选中"≥600 的最近字重"。

## 四、浮窗定位的降级（重建 · 以 `core/float_place.py` 为准）

`place_float(win, w, h, x, y)` 只在与**当前真实几何**不同时才动窗口：

- `win is None` → 原样返回，不抛异常。
- 读 `width`/`height` 失败 → 视为"需要 resize"。
- 读 `x`/`y` 失败 → **宁可移动**（否则窗口再也回不到右上角）。
- `resize`/`move` 抛异常一律吞掉：摆位失败不该影响数据刷新。
- 不缓存位置：缓存里是"上次的目标位置"，而用户可能手动拖走过窗口，
  再点「重置浮窗」时目标与缓存相同就会被判成"没变"，窗口永远回不去右上角。

单独成模块只为一件事：**可以被直接测试**（放在 `controller.py` 里就得 import webview）。
原先配套的验证脚本随 `design-verify/` 一起移除了，改这段请人工核对定位行为。

## 五、进度播报：开场慢放（重建 · 以 `core/site_runner.py` 为准）

**改动前**（`PROGRESS_BURST = 3`）：区域为空时前 3 行**立即输出**——那三行是同一帧里一起冒出来的，
看起来像一次闪烁，而不是"正在一条条抓"。

**改动后**：`PROGRESS_OPENING_DELAYS = (0.0, 0.28, 0.22)`，第 1 行立即出、第 2/3 行分别等
0.28 / 0.22 秒，之后收敛回常规节流 `PROGRESS_MIN_INTERVAL = 0.15`。

**必须一起读的代价**：慢放的 sleep 在 `_progress_lock` 内，而开场行是 worker 真正联网之前播报的，
所以慢放会顺带把前几个并发站点各推迟一次。因此 `PROGRESS_OPENING_BUDGET = 0.5` 秒是**累计硬上限**，
一到就不再慢放（这一版之前它只是注释里的承诺，没有代码执行它）。

**行数上限在前端**：主窗口进度区最多 3 行（`main.js` 的 `PROGRESS_MAX_LINES`），
红浮窗最多 8 条、白浮窗最多 12 条（`floating-common.js` 的 `listLimit`）。
