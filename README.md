# 作业清单 v26.6

一个面向 Windows 10/11 的桌面作业汇总工具。它通过浏览器会话读取已配置学习平台的任务，集中显示在主面板和桌面浮窗中，并支持在浮窗里直接勾选完成。

**v26.6 重点**：① 第一次运行不再空等（没有任何登录状态就不抓，直接显示配置引导）；② 失败处理重做（任何报错只重登一遍，密码错 / 没填账密 / Basic Auth 错第一遍就提示）；③ 不再干等或卡住（登录判定 5 秒、页面内请求 8 秒上限、进度区说明在等哪个站点）；④ 静默默认关，是否静默由用户自己选；⑤ 修 Tyche 截止时间早 8 小时（该平台接口返回的是 UTC 时间）。

---

## 功能

- 汇总多个学习平台的作业与考试，显示课程、起止时间及原网页链接；任务分未完成与已完成两栏，勾选后可随时撤销。
- **红白两个浮窗**：24 小时内到期以及所有已过期的未完成任务进红色紧急浮窗，其余未完成任务进白色提醒浮窗；两个浮窗都能直接勾选完成。
- 可添加、删除手动任务（标题与截止时间必填，课程与链接可选）。
- **填好账号密码后自动后台登录**：登录状态失效时程序静默重登，不需要手动操作。
- **登录失败会说清原因**：密码错、还需要一次验证码、平台只支持扫码、网络故障、连不上服务器，分别是不同的话术和按钮，不会一律显示「登录未完成」。
- **抓取报错自动重登一遍**：重登前先丢掉刚判失败的登录记录；只有重登也不管用、或这台机器上没有可用账密（平台只能扫码 / 换了电脑解不开密文）时，才提示「需要登录」或照实报错。
- **密码错、没填账密、Basic Auth 错都第一遍就提示**，不再连续重试。
- 可在设置中启用或停用站点、填写账号密码、清除会话、删除站点；Tyche 另外支持配置 Basic Auth。
- 支持 Windows 开机自启动；启动后的**首轮**抓取会先等网络就绪（最多 120 秒）。
- **抓取时有进度文字区**：显示正在检查网络、哪个站点开始抓取、抓到了几条、还剩哪些站点在抓；最多 3 行，抓完自动收起，把空间还给任务列表。
- **启动行为与外观可选**：可让每次启动都静默抓取，或直接显示界面（默认）；外观支持跟随系统 / 浅色 / 深色三态，三个窗口实时同步。

### 自动登录是怎么工作的

在设置里给站点填好账号密码后，抓取时如果发现登录状态失效，程序会自动**分两层**尝试：

1. **无头浏览器**静默登录。这是一般站点的正常路径（Tyche、数你最灵、U 校园）。
2. **屏幕外真实窗口**。如果站点会挑战无头浏览器（清华 SSO 就是这样），程序改用真实窗口，把窗口放到屏幕坐标之外，登录完成后立即关闭。
3. 两层都失败（例如确实需要手工输入短信验证码）才会提示用户处理。点「登录」后，窗口里的账号密码已经自动填好，通常只需要输入验证码。

> 屏幕外窗口终究是真实窗口，因此**任务栏上可能短暂出现一个图标**。它不会出现在屏幕可见区域，也不会抢焦点，登录完成后自动关闭。之所以不改成「最小化」，是因为窗口必须先创建出来才能最小化，创建那一瞬间仍会在屏幕中间闪一下；而屏幕外位置在窗口创建时就已指定。

关于清华的两个平台（网络学堂、清华 OJ），它们都走清华统一身份认证（SSO）：

- 会话**还有效**时直接复用，几秒完成，不触发 SSO。
- 会话**失效**时，SSO 会拦无头浏览器并要求二次验证、但放行真实窗口；实测屏幕外真实窗口可以直接登录成功，因此这两个平台也能做到全自动 —— 前提是账号当时没有额外触发短信验证。
- 无头在这两个站点是**必定**失败的，程序直接跳过无头那一档，省掉一次注定失败的登录。

为避免反复去撞 SSO，后台登录失败后有冷却时间：需要验证码的等 **10 分钟**，密码错或 Basic Auth 错的等 **30 分钟**，期间不再自动尝试。在设置里重新填写账号密码会**立即清掉该站点的冷却与旧会话**。

## 抓取失败时会发生什么（v26.6）

| 失败类型 | 登录记录 | 之后会发生什么 |
|---|---|---|
| 页面跳到登录页 / 接口回 401、403 | 决定重登时丢弃 | 静默重登一遍；仍失败则提示「需要登录」 |
| 会话文件损坏 | 丢弃（自愈） | 静默重登一遍；仍失败则提示「需要登录」 |
| 抓取超时（等满 5 秒没内容、又没有任何失效信号） | 丢弃 | 静默重登一遍；仍失败则照实报「抓取超时」 |
| 接口 5xx / 页面改版 / 浏览器崩溃 | 决定重登时丢弃 | **也重登一遍**；仍失败则照实报错 |
| 平台明确回「用户名或密码不正确」 | 丢弃 | **第一遍就停下并提示**，30 分钟内不再自动尝试 |
| 没填账号密码（且没有可用会话） | 不丢弃 | **第一遍就提示**，不起浏览器、不发请求 |
| Tyche：登录页打开但没有账号密码输入框 | 丢弃 | **第一遍就提示** Basic Auth 有误，引导重填 |
| 网络不可达（连不上服务器） | 不丢弃 | **不重登**，直接提示连接校园网/VPN 后刷新 |
| 该站点在失败冷却期内 | 不丢弃、不登录 | 沿用上次的话术（例如「账号或密码有误」） |

规则要点：

- 一次刷新里最多**重登一遍**（即最多抓两次）。每次重登都是真实登录（含浏览器启停约十秒），连续重试只会让用户干等。
- 决定重登时会先**丢掉那份刚判失败的登录记录**，逼这一轮做一次真实登录。旧会话留着的话，程序会先拿它去试，只要首页还能打开就以为「重登成功」，于是反复空转、密码错也判不出来。
- 只有**确定登得回来**才丢会话：平台不支持账密登录（雨课堂只能扫码）、没填账密、密文在这台机器上解不开（换了电脑）、或该站点还在冷却期内 —— 这些情况既不丢会话也不发起登录。平台对「密码错」有明确信号，程序不需要靠「再试一次」确认，收到就当场说出来。

**实际要等多久**（本机实测：网络学堂 + 故意填错密码）：

| 阶段 | 耗时 |
|---|---|
| 抓取（会话预检 1 秒 + 数据等待 5 秒 + 浏览器启停） | 约 6.5 秒 |
| 真实重登：其中**判定出「密码错」只用 2.1 秒**，其余约 6.5 秒是 Playwright 退出浏览器的固定开销 | 约 8.6 秒 |
| **首次刷新合计** | **15.1 秒** |
| 之后再刷新（30 分钟冷却期内，不再发起登录） | **0 秒**，直接给提示 |

**两条「不会再干等」的保证**：

- **登录判定预算 5 秒**（只算「提交之后」的等待）：提交 3 秒后仍停在同一个登录表单、也没有二次验证界面，就直接判账号密码不对，不再傻等到超时；无头层等到超时后也不会再用屏幕外窗口重试一轮。
- **页面内接口请求上限 8 秒**（`auth.guard_in_page_fetch`，给页面里的 `window.fetch` 套超时）：服务器接下连接却不回包时，请求会超时失败并上报，不会让抓取线程永久卡住。同时进度区只要有站点没抓完就显示「仍在抓取 N 个站点：…」，不会出现「其它站点都显示已获取、界面却一直不动」的情况。

**Tyche 两条现场提示**（都可以直接照做）：

- **「Tyche 的 Basic Auth 账号或密码有误，请重新填写」**：登录页打开了却没有账号密码输入框 —— 即 Basic Auth 那一对凭据没填或填错（Tyche 整个站点在 Basic Auth 之后，服务器回 401，页面上自然没有表单）。点按钮打开的就是填账号密码的窗口，Tyche 会显示 **Basic Auth** 两项，重填即可。
- **「无法连接到 Tyche（ERR_CONNECTION_TIMED_OUT）：该站点需要校园网/VPN。请连接校园 VPN 后点「刷新任务」重试。」**：这台机器现在连不到 Tyche 服务器。程序识别 Chromium 的 14 个网络错误码（超时、拒绝连接、域名解析失败、网络断开等），命中就**终止这一轮** —— 连不上时再跑一次自动登录毫无意义，所以不会再白跑。

**出错时的提示是有保证的**：每条错误都写明具体原因（不会出现「抓取失败」后面什么都没有），并附上最近几行诊断摘要；后端将来新增的失败原因会自动退到通用话术，不会变成空白。

## 界面与主题（v26.5）

- **三个窗口共用一份主题表**：主窗口、红色紧急浮窗、白色提醒浮窗统一引用 `web/theme-shared.css`（各自在**自己的样式表之前**引入），不再出现同一套颜色变量写三遍、改一处漏两处的问题。
- **浅色 / 深色 / 跟随系统**三态，在设置面板「外观」里切换；三个窗口通过 `localStorage` 与 `storage` 事件实时同步，不需要重启；**选择会被记住** —— 界面外壳的数据写在程序数据目录下的 `webview\`，重开程序仍是你上次选的那一档。
- **界面用系统字体**：拉丁 `Times New Roman` + 中文`楷体`（KaiTi），离线可用、不发网络请求；表单控件强制继承同一套字体，不再出现「按钮是 Arial」的混搭。仓库与安装包都**不再分发字体文件**（原先随包的 3 个 `.ttf` 是商业字体，已移除）；机器上没有楷体时按 `华文楷体` → `Microsoft YaHei` → 通用 serif 依次兜底。

浮窗列表**不再截断条数**，超出部分在窗口内滚动；窗口高度上限按紧急窗 4 行、待办窗 6 行计算，因此条数变多不会让浮窗无限长高。

## 启动与第一次运行（v26.6）

**启动行为**（设置里的两个开关，改完立即写入 `sites.yaml` 的 `startup_mode`，下次启动生效）：

- `开机自启动`：开启后每次开机并联网自动启动。
- `启动时静默`：开启时每次启动都不出现窗口，只在后台把任务抓好，需要看任务时点浮窗的「主面板」；关闭则启动就出现窗口，能直接看到进度文字区逐行滚动。**出厂默认是关闭**（直接显示界面）。旧配置里已经有这个键就沿用你的设置；没有这个键时，`data/` 里已有会话文件的按「静默」沿用旧行为，全新机器才默认显示界面。

**第一次运行**（一个登录会话都没有、也还没填账号密码）：程序**不会**去抓作业 —— 那一轮的结果必然是「需要登录」，代价却是最多 120 秒网络等待加上每个站点各拉起一次浏览器。现在的行为是：

1. 立即显示主窗口（即使启动行为设成静默也一样：此时还没有登录状态，必须看得见入口）；
2. 顶部给出一条引导，列出待配置的站点，点站点按钮即可填账号密码；
3. 填完（或点「添加任务」手动记一条）之后一切照旧：正常登录、正常抓取、正常刷新。

只要填过任意一个站点，或任意一个站点已有会话文件，下次启动就回到正常抓取流程。

浮窗只在任务刷新或任务状态改变时更新，不按固定间隔主动抓取（它每秒只问一次主窗口是否可见，用来切换「主面板 / 收起」按钮状态）。

## 运行

### 使用打包版

解压程序文件夹后运行 `HomeworkTasks.exe`（`_internal\` 目录必须与它放在一起）。首次启动会根据 `sites.yaml.template` 生成 `sites.yaml`，并创建 `data/` 运行数据目录。

打包产物里只有程序本身（页面、样式、脚本、平台适配器、浏览器驱动），**不包含**你的 `sites.yaml`、`data/`、日志或备份文件；字体也不在包里（界面直接用系统字体）。

### 从源码运行

需要 Windows、Python 3.10 或更新版本（开发与验证环境为 3.12），以及已安装的 Microsoft Edge：

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirement.txt
.\.venv\Scripts\python.exe app.py
```

依赖只有三项：`pywebview>=5.0`、`playwright>=1.40`、`PyYAML>=6.0`。`start.bat` 用于源码模式下的开机启动：优先使用项目里的 `.venv\Scripts\pythonw.exe`，找不到才退回系统 Python。

### 打包

仓库**不含** PyInstaller 配方（`HomeworkTasks.spec` 已按需求移除）。安装 PyInstaller 后运行：

```powershell
.\.venv\Scripts\python.exe -m pip install pyinstaller
.\.venv\Scripts\python.exe -m PyInstaller --noconsole --name HomeworkTasks `
  --icon icon.ico --add-data "web;web" --add-data "sites.yaml.template;." `
  --collect-submodules playwright --collect-binaries playwright --collect-data playwright `
  --exclude-module playwright.async_api app.py
```

这里刻意**不用 `--collect-all playwright`**：那会把 Playwright 自己的 `.py` 源码当数据文件塞进包（63 个文件、约 1.4 MB），还会带上本项目用不到的异步 API。上面的配方按类型精确收集，包内 Playwright `.py` 源码为 0 个；`--exclude-module playwright.async_api` 连异步 API 的字节码都不生成（本项目只用 `sync_playwright`，已用冻结探针真启动 Edge 验证过）。

结果位于 `dist/HomeworkTasks/`。发布前再做一次清理（文件夹约省 5.6 MB）：

```powershell
$d = "dist\HomeworkTasks\_internal"
Get-ChildItem $d -Recurse -File | Where-Object { $_.Name -like "*.d.ts" -or $_.Extension -eq ".map" } | Remove-Item -Force
Remove-Item "$d\playwright\driver\package\lib\vite" -Recurse -Force
```

第二步删的是 Playwright 的测试报告 / 追踪查看器 / 录制器界面（只在 `show-report`、`show-trace`、`codegen` 里用到）；删掉后仍能真启动 Edge 并操作页面，已验证。

> 发布前请确认分享包里没有你自己的 `sites.yaml` 或 `data/`。**运行过一次产物里的 exe 后，它会在产物目录里就地生成这两项，压缩分享前要先删掉。**

### 包体说明（约 127 MB / 271 个文件，标准 zip 约 50 MB）

- `_internal\playwright\driver\node.exe` 一个就 **89 MB**：这是驱动浏览器做自动登录的 Node 运行时，不是浏览器本身。浏览器用的是**系统已安装的 Edge**，没有把 Chromium 打包进去 —— 否则还要再加一百多 MB。
- 其余是 Python 运行时与依赖：`python312.dll` 6.6 MB、`libcrypto`/`libssl` 5.8 MB、`pythonnet`（pywebview 用）3.2 MB、`sqlite3.dll` 1.5 MB 等。
- **功能不变的前提下，能减的已经减完**：仓库内死定义 0 处、未用导入 0 个；包内 Playwright `.py` 源码 0 个；报告界面已剔除。再往下减就得动那个 89 MB 的 Node 运行时，也就是放弃自动登录与自动抓取。

## 首次配置

1. 启动后打开「设置」，启用需要的平台。
2. 给需要的站点点「填账号密码」：数你最灵还要填「学校全名」（例如 `XX大学`），登录前必须先选学校；Tyche 有两组账号密码 —— **Basic Auth** 是打开网站时浏览器弹窗用的那对，**网站账号密码**是网站内部的登录，两组都要填；雨课堂只能微信扫码，不需要填账号密码。
3. 清华的系统（网络学堂、清华 OJ）会自动尝试后台登录；如果弹出浏览器窗口，说明需要输入一次验证码，窗口里账号密码已自动填好。
4. 如需开机启动，在设置中打开对应开关；想要深色界面，在「外观」里选「深色」或「跟随系统」。

## 日常操作

- **刷新任务**：重新访问启用的平台；抓取期间保留当前列表，完成后更新。多个平台**同时**抓取（默认 3 个并发），耗时约等于最慢的那个；可用环境变量 `HOMEWORK_BOT_WORKERS` 调整（设为 `1` 退回串行）。
- **自动重登**：登录状态失效时自动完成，无需操作；只有需要验证码时才会提示。
- **添加 / 完成任务**：添加自己的事项，在主面板或浮窗勾选完成，可随时撤销。
- **管理站点**：设置中的开关、清除登录、删除等更改需点「应用」后生效。
- **填账号密码**：改完会清掉该站点的旧会话与自动重登冷却，下次刷新用新账号重新登录。
- **控制浮窗**：标题栏「主面板」切换主窗口；「—」最小化该浮窗；「×」关闭该浮窗。主面板的「重置浮窗」可重新显示被关闭或最小化的浮窗。
- **退出程序**：关闭主窗口会退出程序并关闭浮窗；单独关闭浮窗不会退出主程序。

## 本地数据与隐私

程序默认把数据放在项目目录（打包版为 exe 同级目录）。如果这个位置不可写（例如解压到 `Program Files`），会改用 `%LOCALAPPDATA%\HomeworkTasks`，并尽量把原有的 `sites.yaml` 与 `data/` 复制过去；**界面顶部会有横幅说明实际使用的目录**，不会悄悄换地方。

生成的文件：

- `sites.yaml`：站点启用状态与配置；账号密码（含 Tyche 的 Basic Auth 凭据）**加密后**保存于此。
- `data/homework.db`：手动任务与完成状态。
- `data/*_session.json`：各平台的登录会话；`data/*_courses.json`：部分平台的课程缓存。
- `webview/`：**界面外壳**（WebView2）的数据目录，只存主题这类界面偏好与本地页面缓存（约十几 MB）；删掉它只会让主题回到「跟随系统」，不影响账号、会话与任务。

这些文件可能包含账号凭据、登录状态或个人任务，不要发送给他人或提交到公开仓库。备份个人设置时可单独备份 `sites.yaml` 与 `data/`；分享程序时则应排除它们（`webview/` 可留可删）。仓库的 `.gitignore` 已忽略 `sites.yaml`、`*.bak`、`data/`、`*.db`、`*_session.json`、`*_courses.json`、`webview/`。

其他几条数据安全约定：配置读不出来时**拒绝写入**，绝不拿一份空配置覆盖磁盘上的文件；界面绝不把「抓取失败」显示成「全部完成」；会话文件与配置都走原子写，避免留下半截文件。

### 账号密码是怎么加密的

`sites.yaml` 里的账号和密码用 **Windows 自带的 DPAPI** 加密，存储为 `enc:v1:...` 形式。密钥由 Windows 按当前登录账户托管，因此：

- 程序能自己解开，**不影响开机后台自动抓取**，不需要额外输入任何密码；
- 换一台电脑、或换成另一个 Windows 账户，这些密文**解不开**（这是特性，不是缺陷）；程序会把该站点显示为「密码需重新填写」，在设置里重填一次即可；
- 旧版本留下的明文账号密码会在**首次启动时自动加密**；如果这一步失败，界面会明确提示「磁盘上可能仍是明文」，而不是静默假装成功。

边界要说清楚：**这挡的是「文件被别人看到」**（误传网盘、被同步工具上传、误提交进仓库），**不是「防住本机恶意软件」** —— 任何以你的身份运行的程序都能调用 DPAPI 解密。

## 常见问题

**提示需要登录怎么办？** 提示条会写明原因并给出对应按钮：需要验证码点「输入验证码」；账号或密码有误点「重新填写账号密码」；只支持扫码的平台点「扫码登录」。仍不行时，在设置中清除该平台的登录状态后重新登录。

**Tyche 提示 Basic Auth 有误 / 无法连接？** 前者说明 Basic Auth 那一对（打开网站时浏览器弹窗用的账号密码）没填或填错，点按钮重填即可；后者说明这台机器现在连不到 Tyche 服务器，连接校园 VPN 后点「刷新任务」即可，程序不会为这种连不上的情况白跑一次自动登录。

**为什么密码错要等十几秒才提示？** 因为这十几秒里做了两件事：先抓一次（约 6.5 秒，含 1 秒会话预检与 5 秒数据等待），再用真实登录验证账号密码（约 8.6 秒）。其中**判定出密码错只用 2.1 秒**，其余约 6.5 秒是 Playwright 退出浏览器的固定开销，与网络无关。提示出现后进入 30 分钟冷却，之后刷新立刻给出同样的提示。

**红色浮窗没有显示？** 没有 24 小时内到期、也没有已过期的未完成任务时，红色浮窗会隐藏。**过期多久都算紧急**（v26.6 取消了早先「过期超过 3 天降级到白窗」的下限），所以红窗里出现几个月前就该交的作业是预期行为，排序按过期越久越靠前。

**开机后没有任务？** 程序启动后的**首轮**抓取最多等待网络 120 秒（之后的「刷新任务」不再等待），网络恢复后点「刷新任务」重试即可。如果一个登录会话都没有（第一次运行、或删过 `data/`），启动那一轮根本不会去抓，而是直接显示界面让你先填账号密码。

**如何清空任务和登录状态？** 退出程序后，删除 `data/` 会清除数据库、会话与缓存；删除 `sites.yaml` 会在下次启动时按模板重新生成。
